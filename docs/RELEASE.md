# Release Preparation

1. **Product & runtime criteria**: All product acceptance criteria (`docs/PRODUCT_BRIEF.md`), automated unit/integration suites (`timeout 180 npm test`), strict TypeScript checks (`npm run check`), official ESLint checks (`npm run lint`, `--max-warnings=0`), Python/Node client syntax checks (`py_compile`, `node --check`), build gates (`npm run build`), and isolated headless Obsidian `1.15.0` E2E runtime checks (`docs/ACCEPTANCE.md`) are executed and recorded.
2. **Official policies & disclosures**: Reviewed against `docs/SOURCES.md`. Desktop-only process spawning (`node:child_process`), local IPC sockets (`herdr` socket + mode-`0600` Vault Control Bridge), vault mutation permission tiers, and zero external network/telemetry behavior are explicitly disclosed in `README.md`.
3. **License & third-party notices**: MIT License in `LICENSE` for the plugin, except the UI control module `src/control/`, which is Apache 2.0 (`src/control/LICENSE`, attribution in `NOTICE`, SPDX header enforced on every `src/control/*.ts` by `esbuild.config.mjs`, banner at the top of `main.js`); bundled `@xterm/*` MIT notices and clean-room boundaries recorded in `THIRD_PARTY_NOTICES.md`; `package.json` `"license": "MIT AND Apache-2.0"`. Releases attach `LICENSE`, `LICENSE-Apache-2.0.txt`, and `NOTICE` next to the plugin files.
4. **Version & compatibility alignment**:
   - `manifest.json`: `"id": "herdr-obs"`, `"name": "Herdr Mission Control"`, `"version": "0.3.2"`, `"minAppVersion": "1.14.4"`, `"isDesktopOnly": true`
   - `package.json`: `"name": "herdr-obs"`, `"version": "0.3.2"`
   - `versions.json`: maps `"0.3.2": "1.14.4"` (verified automatically by `.github/workflows/release.yml`, which rejects `v`-prefixed or mismatched tags).
   - Release assets required for GitHub Release (bare semver tag without `v` prefix): `main.js`, `manifest.json`, `styles.css`.
5. **Multi-OS CI & verification honesty**: `.github/workflows/ci.yml` runs `check`, `lint`, `build`, `py_compile`, `node --check`, and `npm test` across `ubuntu-latest`, `macos-latest`, and `windows-latest`. Live Obsidian desktop verification has been run on Linux; macOS and Windows paths are covered by unit tests and multi-OS CI rather than live desktop sessions on this host.
6. **Artifact hashes & rollback**: Exact byte sizes and SHA-256 digests are recorded in `docs/ACCEPTANCE.md`. Rollback means restoring the previous tested `main.js`, `manifest.json`, and `styles.css`.
7. **Owner approval gate**: Do **not** push to a remote repository, create a GitHub release tag, submit a PR to `obsidianmd/obsidian-releases`, or copy build artifacts into an active vault without explicit authorization from Daniel Agrici.
